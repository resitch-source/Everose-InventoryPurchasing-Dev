Login & Branch Access

Everose ERP uses a PIN-based multi-user login system. Each account is tied to a branch. The Managing Director can access all branches via a topbar dropdown.

Login Flow

1
Login Screen on startup
The login screen appears before any ERP screen. If a session is stored in localStorage key everose_auth_v1, the user is restored automatically and login is skipped.
2
Select account
Four user cards are shown. Clicking a card sets the selected user and reveals the PIN numpad.
3
Enter 4-digit PIN
Auto-submits after the 4th digit. Wrong PIN triggers a CSS shake animation and clears the input. No lockout policy — retry is immediate.
4
Session stored
On success, the user object is saved to localStorage so the session persists on page reload. A toast confirms: "Signed in as [Name] · [Role]".

Branch Access & POS Routing

The active branch (warehouse) is determined by the login session:

  • Cashier login: Active branch is fixed to their assigned warehouse. A badge in the topbar shows the branch name. The POS deducts stock from that warehouse.
  • Managing Director login: Active branch defaults to WH-ILIGAN but can be switched via a dropdown in the topbar. All screens (inventory views, POS, receipts) update to reflect the selected branch.
ℹ️
Receipt Attribution
Each completed sale stores cashier: currentUser.name and wh: activeBranch in the sale data. The printed receipt displays the cashier's name and the branch warehouse name, providing a clear audit trail per transaction.

Sign Out

Click the ✕ (sign out) button next to the user name in the sidebar footer. This clears everose_auth_v1 from localStorage and returns to the Login Screen. Recommend signing out when leaving a shared device unattended.

⚠️
PIN Security Note
PINs are stored in the USERS constant in the HTML source. For production deployments, move user credentials to a server-side authentication layer. The current PIN system is suitable for trusted-device, internal-use scenarios only.

Updating User PINs (Admin)

To change a PIN or add/remove users: open the HTML file in a text editor, locate the const USERS = [...] array near line 6462, and update the pin field for the relevant user. Save the file. All devices using that file will pick up the change on the next page reload.

Complete Sale Workflow

1
Add products to cart
Search by name/SKU, scan barcode, or click popular item tiles. Each product shows current stock — you cannot add more than available stock.
2
Adjust quantities & apply discount
Edit qty in cart. Apply a whole-sale discount % (e.g. 10 for 10% off entire sale). Discount is shown as a line before total.
3
Select customer (optional)
Search by name or phone. Default is "Walk-in Customer." Account customers have their AR balance checked against credit limit when using In-House Credit.
4
Click Proceed to Payment
Payment modal opens with total shown prominently.
5
Select payment method(s) & enter amount
Select one or multiple payment methods. For cash, enter the tendered amount — change is computed automatically.
6
Complete Sale
System: (a) deducts stock from the active branch warehouse (activeBranch), (b) posts sales journal entry, (c) updates customer AR if credit sale, (d) displays receipt with cashier name and branch. Sale ID is generated (e.g., SO-12481).
7
Print receipt
Click Print Receipt. Browser print dialog opens. Select printer or Save as PDF. Receipt shows itemized products, payment breakdown, customer name, and store info.

Barcode Scanning in POS

1
Click the 📷 camera icon
Located next to the search bar. Camera activates immediately.
2
Point at barcode
Hold barcode 10–20 cm from camera in good lighting. Scanner detects automatically — no button press.
3
Product added instantly
Matching SKU is added to cart. Scanning the same barcode again increments quantity.
⚠️
Credit Limit Enforcement
If a customer's balance would exceed their credit limit after an In-House Credit sale, the system displays a warning. You can still proceed with supervisor approval, or switch to a different payment method.

Deleting a Product

⛔
Irreversible — Administrator Action Only
Deleting a product permanently removes it from all screens, stock counts, and future reports. Historical movements referencing the SKU remain in the journal. Always export a backup before deleting products.

To delete: Open product → Edit → scroll to bottom → Delete Product → Yes, Delete Permanently (two-step confirmation).

Creating a Purchase Order

1
Click "+ Create PO"
Available from the Purchase Orders screen. Or go to a Supplier card and click "Create PO" to pre-fill supplier.
2
Select supplier
Supplier's payment terms and lead time auto-populate. ETA is calculated as today + lead days.
3

Submit PO
Status → Open. "On order" count updates for each product on the Inventory screen.

Overdue POs

POs where the ETA has passed and status is not "Received" are flagged as Overdue. They appear in:

  • The Dashboard KPI strip (orange "X overdue" badge)
  • The Notification Panel as Warning or Critical alerts
  • A red row highlight in the Purchase Orders table

Data Management & Backup

All data is stored in the browser's localStorage. Regular backups are mandatory. Click the 🗄 Data button in the top bar to access all backup and sync tools.

⛔
Critical Warning — Browser Storage
Clearing the browser cache, "Clear site data," or uninstalling the browser WILL permanently delete all ERP data. Export a JSON backup at minimum once per week. Store backups in multiple locations: local drive, USB, Google Drive, email attachment.

How to Update a PIN

1
Open the HTML file in a text editor
Right-click Inventory & Purchasing.html → Open with → Notepad (Windows) or TextEdit (Mac). Use VS Code for a better experience.
2
Find the USERS array
Search for const USERS = [ (around line 6462). Each entry has id, name, role, pin, wh fields.
3
Change the pin field
Update the pin: "XXXX" value. PINs must be exactly 4 numeric characters. Example: pin: "5678".
4
Save and refresh
Save the HTML file. Reload the page in the browser. The new PIN is active immediately — no restart required.

How to Add a New User

Add a new entry to the USERS array with a unique id, name, role, 4-digit pin, and wh (warehouse ID or "all" for full access). Example:

{ id: "U-005", name: "Dan Soriano", role: "Cashier — Iligan 2", pin: "4444", wh: "WH-ILIGAN" },

Save the file and reload. The new user appears on the Login Screen immediately.

⚠️
Security Reminder
PINs are stored in plain text inside the HTML file. For sensitive deployments, implement server-side authentication. The PIN system is designed for trusted internal devices and low-risk operational environments. Do not use the same PIN as your bank or personal accounts.

Deployment Options

Everose ERP can be accessed in several ways. Choose the method that fits your team size and infrastructure.

💾
Local File (Default)
Open the HTML file directly in a browser. Works immediately, no setup. Each device has its own data. Best for single-location use or testing.
🌐
GitHub Pages (Free)
Upload to GitHub repository and enable Pages. Creates a permanent URL accessible from any browser. Free hosting.
☁️
Netlify / Vercel
Drag-and-drop the HTML file at netlify.com. Instant free hosting with HTTPS. No account needed for basic use.
📁
LAN Server (Python)
Run python -m http.server 8080 in the folder. All devices on the same WiFi can access via http://[your-ip]:8080
💡
Multi-Branch Access
For all 3 Everose locations to access the same instance: deploy to GitHub Pages or Netlify to get a public URL. Each branch can access the same URL from any device. Note: data is still stored locally per browser — use Google Sheets sync to share data between branches.
⚠️
iOS/Mobile Barcode Scanning
Camera access requires HTTPS. Local file:// URLs and http:// LAN servers may not grant camera permission on iOS. Use GitHub Pages or Netlify (both HTTPS) for mobile barcode scanning.

Frequently Asked Questions

Q: Can multiple people use the system simultaneously?

Each browser has its own localStorage — data from one browser doesn't sync to another automatically. Use Google Sheets sync or daily JSON export/import to share data between devices. For true real-time multi-user, a server deployment is needed.

Q: My data disappeared. What happened?

Browser data was likely cleared (cache clear, private/incognito mode, browser reinstall). Always maintain daily JSON backups. To restore: Data panel → Import JSON → select your most recent backup file.

Q: Barcode scanner shows camera but won't scan.

1) Check lighting — hold barcode under good light. 2) Check distance — 10–20 cm is optimal. 3) Make sure barcode is flat and unobstructed. 4) On iOS, use Safari and ensure camera permission is granted in Settings → Safari → Camera.

Q: WhatsApp/Viber notifications open the app but don't auto-send.

This is by design — the system opens the app with the message pre-written, but you must press Send in the messaging app. This gives you a chance to review or add context before sending.

Q: Can I add more suppliers or warehouses?

Currently, suppliers and warehouses are configured in the HTML source file. Contact your system administrator (or the Nexarch/Cyrabell technical team) to add new suppliers. A user-facing supplier management form is planned for a future update.

Q: How do I process a customer refund?

1) Add the returned items back to stock via Stock Adjustment (type: Physical Count — increase by returned qty). 2) Reduce the customer's AR balance manually or create a credit note in the journal. 3) Issue a replacement or refund payment as appropriate. Consult your accounting procedure manual.

Q: The system is slow on mobile.

Close other apps and browser tabs. Use Chrome (Android) or Safari (iOS) for best performance. On very large inventories (500+ products), the ledger view may be slower — switch to Stock Board or Command view for faster rendering.

Q: Can I change the currency from Philippine Peso?

The ₱ symbol is hardcoded throughout the application. Contact your administrator to modify the source HTML file if a different currency symbol is needed.
